# Team Contribution & Execution Plan: Kabhi Code Kabhi Bug

This document outlines the strict division of labor for building the Hedge Fund Risk Modeling System. To avoid Git conflicts and ensure we finish before the deadline, stick strictly to your assigned domain.

## Team Member 1: The Data Engineer
**Your primary goal:** Turn messy CSVs into a single, flawless, queryable timeline.
**Your working directory:** `backend/data_pipeline/`

### Responsibilities:
1. **Data Ingestion (Issue 1):** Write `loader.py` to use `pandas` to read the 4 CSV files in the `data/` folder and merge them on the `Date` column.
2. **Missing Data Imputation (Issue 2):** Write logic in `preprocessor.py` to fill the empty `SMA_10` and `Returns` cells using backward/forward filling. Do NOT introduce forward-looking bias.
3. **Macro Alignment (Issue 4):** Resample the monthly `macro-dataet.csv` to map correctly onto the daily trading timeline.
4. **Data Validation (Issue 16):** Ensure the final DataFrame drops or skips corrupted rows safely.

**Your Deliverable:** A Python function `get_clean_data()` that the Quant Engineer can import into their simulation loop.

---

## Team Member 2: The Quant Developer
**Your primary goal:** Build the mathematical brain that makes trades, applies real-world friction, and prevents catastrophic losses.
**Your working directory:** `backend/engine/` and `backend/main.py`

### Responsibilities:
1. **State Management (Issue 5):** Build the `PortfolioManager` class in `portfolio.py` to track starting capital and available cash.
2. **Signal Generation (Issue 8):** Build the `SignalGenerator` class in `signal_generator.py` to output "Buy/Sell" based on the `SMA_10` column.
3. **Risk Management & Slippage (Issues 6, 9, 10):** Build the `RiskManager` class to gatekeep trades using Value at Risk (VaR). Before updating the `PortfolioManager` state, your code MUST subtract a simulated transaction fee and slippage penalty. 
4. **API Integration:** Wrap your simulation loop inside a FastAPI endpoint in `main.py` (`/api/simulate`) so the frontend can trigger it.

**Your Deliverable:** An API endpoint that accepts risk parameters, runs the historical loop, and returns a JSON payload containing daily portfolio values and a log of every trade made.

---

## Team Member 3: The Full-Stack / Analytics Engineer
**Your primary goal:** Calculate the final financial proof and build the "Wow Factor" dashboard for the judges.
**Your working directory:** `frontend/src/` and `backend/api/metrics.py`

### Responsibilities:
1. **Financial Metrics (Issues 7, 12, 13):** Write the Python math in `metrics.py` to calculate the Sharpe Ratio, Alpha, Beta, and Maximum Drawdown based on the final array generated by Member 2.
2. **Dashboard UI (Issue 18):** Scaffold the Next.js app. Build the `PerformanceChart.tsx` using Recharts to visualize the equity curve.
3. **Explainability Logs (Issue 14):** Build the `TradeLogTable.tsx` component to map over the JSON response and display exactly *why* the Quant Engine made a trade, satisfying the "explainability" requirement.
4. **Documentation (Issue 19):** You are responsible for ensuring the `README.md` perfectly matches the required submission format. Do not alter the headings in the provided template.

**Your Deliverable:** A polished, interactive React dashboard that proves our algorithm safely managed risk and generated returns.
